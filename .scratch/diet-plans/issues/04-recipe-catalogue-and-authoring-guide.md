# Recipe catalogue and the authoring guide

Type: task
Status: ready-for-agent
Blocked by: 03

## What to build

**`content/diets/catalogue.js`** (also `npm run catalogue`) validates every Recipe with `lib/recipes.js` and every plan's references, then writes `recipes/INDEX.md`. That file is how the next Claude finds a Recipe before writing a new one.
- The first line says it is generated by `catalogue.js` and must not be edited.
- One table per slot, in the order breakfast, snack, preworkout, lunch, dinner. A Recipe with several slots appears under each. Rows are sorted by name.
- Columns: key, name, minutes, kcal, protein, carbs and fat at `portion` 1 (raw recipe grams, no size scaling), tags, and "used in" (the plan slugs, with how often each uses it).
- At the end: the Foods in `foods.json` that no Recipe uses, so unused entries are visible.
- `--check` exits non-zero when `INDEX.md` differs from what would be written. `render.js` runs the same check and prints `WARNING recipes/INDEX.md is out of date: run node catalogue.js`.

**README: rewrite "Instructions for Claude filling a diet"** around Recipes. Keep the existing rules that still hold: the reference 80 kg man, the protein targets, Albanian with informal "ti", local foods first, the 5% check, and looking at the PNGs. Add these:
1. Read `recipes/INDEX.md` first. Reuse Recipes that fit by slot, tags and calories. A diet should mostly reuse.
2. Write a new Recipe only when nothing fits. Name its key from the dish's name, never rename a key, and run `node catalogue.js`.
3. Fit calories in the plan with `portion` and `grams`, not by editing the Recipe.
4. Changing an existing Recipe changes every plan in its "used in" column. Re-render those plans, and list for the owner which Products need new PDFs (spec Decision 5). A change that suits only one plan goes in that plan.
5. In a project thread, render with `--out /mnt/project-files/diet-plans/out` and attach the PDFs from there.
6. In the summary for the owner: new Recipes, new Foods (with source), changed Recipes and the plans they affect, and wording you are unsure of.
